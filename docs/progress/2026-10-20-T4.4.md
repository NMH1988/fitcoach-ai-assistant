## 2026-10-20 · T4.4 Tool-calling loop and tool results UI · #49 (closes #14)
- **Brief:** core requirements 2 (three tools the model can call) and 5 (tool results shown); Medium 6 (tool results visualised); AC-6.
- **What:**
  - `src/tools/registry.py` (new): `build_tools(profile)` gives the three tools as `StructuredTool`s with explicit argument schemas: `FoodLookupArgs` for the food lookup, `NoArgs` for `calculate_tdee` and `calculate_macro_targets`, which get the profile when built (the macro tool computes the TDEE itself and uses the profile's goal). `run_tool_call()` checks a call against its schema, runs it and returns the tool message (JSON) and a `ToolRun` for the UI; `refused_call()` answers a call that is not run. Without a profile the energy tools return "profile needed".
  - `src/chat.py`: `answer_with_tools()` binds the tools and runs at most 4 tool rounds (6 calls each), then one call with `tool_choice="none"`; `stream_reply()` replaces `stream_answer()` and refuses a cut-off reply before its tool calls run; `build_messages()` adds a `<profile>` block between `<sources>` and `<user_input>`; `Step.TOOLS` ("Using the tools"); `TurnResult.tool_runs`; `ToolLoopError`; `run_turn(..., user=)`. `PacedWriter` clears the screen on empty text (the text of a tool round).
  - `src/tools/food.py`: `FoodLookupArgs` has `extra="forbid"`; the invalid-arguments message is public (`invalid_lookup_message`) and says "use only the arguments food and grams" for an extra field, without naming it.
  - `src/config.py`: `MAX_TOOL_ROUNDS`, `MAX_TOOL_CALLS_PER_ROUND`, the fixed tool messages, `PROFILE_NEEDED_HINT`, `MACRO_COLORS`.
  - `app.py`: the session's profile goes to `run_turn()`; under each answer, "Tool results (n)" holds each result under a heading, as `st.dataframe` tables, with a stacked bar of the macro split for the targets; "profile needed" shows an "Add your details" button that opens the dialog; the "Using the tools" step has its caption.
  - Tests: `tests/test_tools_registry.py` (schemas, refusals with spies that fail if a tool runs, the profile, failures), `tests/test_tool_loop.py` (the loop with the scripted model and the fixture index), `tests/test_app_tools.py` (AppTest); `tests/fakes.py` gets `bind_tools` and streamed tool calls on `ScriptedChatModel`, a profile, a foods table with a made-up hostile name, and `tool_reply()`. 1,581 tests pass (with `main` merged).
  - Docs: plan (T4.4 in review with tests; new T4.7, issue #44; O1 todo for T4.4; T7.1 depends on T4.7), `docs/ARCHITECTURE.md` (sections 2, 3, 6, 7, 10), `docs/UI_DESIGN.md` (Tool results, T4.7 rows), `docs/SECURITY.md` (tool arguments, cost, profile, plain-text tables, a known limit on links), screenshot `docs/ui/t4.4-tool-results.jpg`.
- **Why:** an own loop (D2) keeps each round visible and testable with a fake model. The tools get the profile from the app, so the model can neither invent body data nor change it, and the T1.4 audit's finding 2 (the `table` hook as a model argument) cannot happen. A schema check of our own is needed because LangChain does not check a schema without fields. Tables in `st.dataframe` keep USDA names as text (finding 4); `st.table` would render Markdown links and images in them.
