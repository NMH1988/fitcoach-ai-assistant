## 2026-10-25 · T1.8 A fixed message for unexpected errors in a chat turn · #120 (closes #82)
- **Brief:** Sprint 3 (`docs/BRIEF_SPRINT3.md`): core 4 (proper error handling, real-world use), evaluation: core concepts (error scenarios and edge cases) and technical (appropriate security: no error text on the page), Sprint 2 review point 1 in part (an unexpected error leaves a log line). Sprint 2 (`docs/BRIEF.md`): core 4 (proper error handling), Medium 10 in part (logging), evaluation: core concepts (error scenarios and edge cases) and technical (appropriate security). PRD AC-13.
- **What:**
  - `src/chat.py`: `run_turn()` catches any other `Exception` after the named ones, logs one ERROR line with only the error's type and the function that raised it, and returns an `"error"` result with `TURN_ERROR_MESSAGE` (code `turn.error`), the steps run and the tokens spent so far. A module logger (`logging.getLogger(__name__)`) is added.
  - `src/llm.py`: `_diagnostic()` is now the public `error_diagnostic()`, so the catch-all builds its log line the same way as `LLMError.diagnostic`.
  - `src/config.py` (`TURN_ERROR_MESSAGE`), `src/i18n.py` (`turn.error` in English and German).
  - Tests: `tests/conftest.py` fails a test whose turn ends in `turn.error` unless the test carries the new `turn_error` marker (registered in `pyproject.toml`), so the catch-all cannot hide a fake's assertion or a regression; `tests/test_chat.py` (the seven failure points, the tokens kept, German, the log line, no line for a named error, `BaseException` passes through), `tests/test_app_chat.py` (the fixed message in English and then German, the earlier answer kept, no marker on the page).
  - Docs: `docs/ARCHITECTURE.md` section 10 (the catch-all row, and a row for errors outside a turn), `docs/SECURITY.md` (the control, and audit finding 2 fixed), `docs/IMPLEMENTATION_PLAN.md` (T1.8 done, its Serves line in the two-brief format; T9.1 done, merged as #119).
- **Why:** before this, a bug in our code or an unexpected library error ended the turn with Streamlit's generic error box and left no trace. The fixed message keeps the chat usable in the chosen language, and the log line says what failed without its message, which may hold the question, a chunk or a server's reply.
- **Decisions & gotchas:** owner's choices: a new message rather than `llm.error`, which names the model service (2026-10-22); the English and German texts (2026-10-25). The catch-all wraps `guard.run_guarded()`, so a bug in the guard itself also gets the fixed message; no API call has happened at that point. It also catches an error raised in the app's `on_step` or `on_text` callbacks, which could hide a UI bug in an AppTest; the tests that check the answer's content still catch it. There is no log configuration yet: Python's last-resort handler prints the line to stderr until T8.2 adds the JSON logger. `scripts/run_evaluation.py` changes with it: a bug in one question no longer stops the run with a traceback; that question shows the fixed message, the run goes on, stderr gets only the type-and-place line, and the exit code is still 1 (it counts error turns). Debug such a question by running it alone with the catch-all's line as the pointer. An unexpected error keeps the cached index (only `IndexNotReadyError` clears it), as before: rebuilding the index with the app running is still not supported (stop the app first, `CLAUDE.md`).
- **Code review** (round 1, on the uncommitted working tree, before the PR): needs changes, no Must fix, nothing in the code; taken: "appropriate security" and Medium 10 in part added to the Brief and Serves lines, the German text recorded as approved, the `turn_error` marker and the conftest check, the evaluation script's new behaviour written down here, and the nits (the log line's place asserted, the tokens compared in full, no exception after the switch to German). The reviewer's question, whether an unexpected index error should clear the cached index, is left to the owner; the motivating example was reworded instead.
