## 2026-10-20 · T3.4 Prompt injection hardening · #45 (closes #10)
- **Brief:** Medium 3 (prompt injection protection), one of the optional tasks for maximum points; core 3 (security relevant to the domain); AC-11.
- **What:**
  - `src/prompt_data.py` (new) and `src/chat.py`: `escape_prompt_data()` (`html.escape` without quotes: `&`, `<`, `>` as entities, after folding full-width and small-form brackets and ampersands). `format_sources()` escapes each chunk's text, title, year and tier label; `build_messages()` escapes the question. The question is still plain message content, never a prompt template.
  - `src/guard.py`: the delimiter pattern also catches attribute-shaped text (up to five `name=value`) and a closing slash (`<user_input id="2">`, `</sources lang="en">`, `<sources/>`), "user input" written with `-` or a space, and `<source>`; the role-line pattern also catches lines after `**`, `>` or `_` markers (`**System:**`, `> System:`, `__Assistant:__`). Both stay linear (bounded repeats only).
  - Tests: `tests/test_prompt_injection.py` (new): seven look-alikes each in the question, the chunk text and the title and year, with the four delimiters as the only tags in the message and `html.unescape` giving the exact text back; full-width brackets in a chunk; braces stay as typed; no prompt template in `app.py` or `src/`; a turn with a made-up injected chunk sends the same system prompt and request shape as a clean turn, with no tool arguments (`ScriptedChatModel` in `tests/fakes.py` now records `call_kwargs`); the owner's prompt says both blocks are data; an AST scan finds no call passing `unsafe_allow_html` or `unsafe_allow_javascript` by keyword, by position (`markdown`, `caption`), through `*` or `**`, and no `streamlit.components` (the scan itself is tested on small code strings). `tests/test_guard.py`: 12 attack and 10 benign strings, and a speed test on nine worst-case inputs up to 8,000 characters (about 0.01 s each). 1,108 tests pass.
  - Docs: `docs/SECURITY.md` (controls for direct and indirect injection and output; known limits: the new patterns also reject "<user id=1>" or a pasted "> System:" line, look-alikes NFKC does not fold, forged source headers inside a chunk; the escaping note replaces "not yet escaped"), `docs/ARCHITECTURE.md` (steps 2 and 5), plan (T3.4 in review, each criterion with its tests).
- **Why:** the T1.4 audit (finding 3) showed that the guard let delimiter look-alikes through and that the answer step wrapped raw text, so a `</sources>` inside a chunk or a question could end a block early. Escaping removes every `<` and `>` from the data, so no look-alike, known or not, can close or open a block. That is simpler and stronger than adding patterns one at a time. The guard patterns are the first line, which stops the common forms before any API call.
- **Decisions & gotchas:**
  - Owner's choices (2026-10-20): widen the guard's patterns too; leave the answer prompt as it is (it already tells the model to treat both blocks as content and ignore instructions in them).
  - `&` is escaped as well, so a typed `&lt;/sources&gt;` reaches the model as `&amp;lt;/sources&amp;gt;`, never as something that reads like the app's own tag.
  - Only the prompt gets the escaped text. The guard, retrieval (embedding the question) and the UI (the question shown with `st.text`) keep the cleaned text as typed. The model sees e.g. "p &lt; 0.05"; if an answer copies an entity, Streamlit's Markdown shows the character.
