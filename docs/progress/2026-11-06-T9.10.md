- **What:**
  - `scripts/run_evaluation.py --score`: after the questions run, each answered turn is scored on faithfulness (to the chunks the answer model got; `no_chunks` when it got none) and answer relevancy; a turn with no answer is `no_answer` and costs no judge call. The results file gains `scores` per run (a number or a code) and a `scores` section (judge, library, means, counts, tokens, cost); the report gains the scores and the judge's reasons. Exit 1 when the judge failed for an answer or the scoring was stopped. Without `--score` nothing changes, so the baselines still compare.
  - `src/eval_scoring.py`: DeepEval's switches set before its import (telemetry, `.env`, the update check, the local run store), a refusal when a Confident AI key is set, `Judge` (the app's client from `build_chat_model()`, recording its tokens), `score_answer()`; `src/eval_results.py`: `Score`, `RunRecord.scores`, `score_summary()`; `config.EVAL_JUDGE_MODEL` (`openai/gpt-5-mini`), `EVAL_JUDGE_MAX_TOKENS`, `EVAL_SCORE_METRICS`.
  - Dependency: `deepeval==4.3.3` in a new `eval` extra (Apache-2.0, read in its `LICENSE.md`); CI's test job installs `.[dev,eval]`; the licence test walks the extra; DeepEval's pytest plugins and its own warnings are switched off in `pyproject.toml`; `.deepeval/` gitignored.
  - Docs: TESTING (how to run, what the scores mean, what is written, the owner's run and what it shows, the limits), SECURITY (a threat row for the judge and DeepEval; the results-file row; `pip-audit` does not cover the extra), ARCHITECTURE (section 12, the file tree, the brief table), CLAUDE.md and README (install with `.[dev,eval]`, the scored run), the plan (status, issue number, O14).
- **Why:** the ticket asks for the report from the agent's answers and retrieved chunks, which only the evaluation run has in memory, so scoring is a flag on that run rather than a second script that would ask the questions again (and pay again). The judge is wrapped rather than named, so DeepEval never builds a client and the allowlist, the token cap and the error mapping stay the app's. A missing score is a code, never 0, so a guarded question or a judge failure cannot pull a mean down.
