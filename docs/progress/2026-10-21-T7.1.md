## 2026-10-21 · T7.1 Language switch: English and German UI · #74 (closes #33)
- **Brief:** Hard 4 (multi-language support) as an extra after the core; AC-16. Beyond the PRD's original English-only scope (owner's request, 2026-10-20).
- **What:**
  - `src/i18n.py` (new): every UI text in English and German under a key, `t(key, lang, **params)`, `language_for_locale()`, `browser_locale()` (`st.context.locale`), `number()` and `plain()` for the language's thousands and decimal marks.
  - `app.py`: an EN | DE segmented control in the header (`key="language"`, `required=True`, label "Language" collapsed, a `:material/translate:` icon); the language written once from the browser's locale before the control is drawn; every shown text through `_t()`, numbers through `_n()`/`_plain()`; the dialog built each run so its title follows the language; chart labels, tooltips and a German axis format; format functions bind the language when drawn.
  - Message codes from `src/`: `GuardResult.code`/`params`, `LLMError.code` (each subclass, `ToolLoopError` too), `IndexNotReadyError.code`, `PromptMissingError.code`, `TurnResult.code`/`params` (also the key errors and "no sources"), `ProfileError.problems` with `messages_in(lang)`. The English text stays where it was (`TurnResult.text`, `ProfileError.messages`) for the PDF and the existing tests.
  - A `lang` parameter, English by default, on `units.format_weight`/`format_per_body_weight`/`format_grams_per_body_weight`, `usage.format_cost`/`format_tokens`/`format_turn`/`format_session` and the meal plan's table helpers (`food_columns()`, `comparison_columns()`, `food_row()`, `comparison_rows()`, `difference_text()`, `range_text()`); the profile's English messages now come from `i18n`.
  - Tests: `tests/test_i18n.py` (new: keys and placeholders in both languages, "Sie", the locale mapping, number formats, English entries equal to the guard, guardrail, model-error, index, config, profile, status, tier, topic, tool and step texts, every code present), `tests/test_app_language.py` (new, 18 AppTests); `tests/test_app_export.py`'s source scan looks for `_t("theme.hint")`.
  - Docs: plan (T7.1 in review, criteria with their tests), `docs/UI_DESIGN.md` (Language: done, what stays English, numbers), `docs/ARCHITECTURE.md` (folder layout, UI, error handling), `docs/SECURITY.md` and `docs/UI_DESIGN.md` (guard messages now German in the German UI), `docs/TESTING.md` (browser check), two screenshots in `docs/ui/`.
- **Why:** keys and codes keep one English source per text for the model and the PDF, while the UI can show any message, past ones too, in the language chosen now. Defaults of English everywhere in `src/` keep the PDF, the `<profile>` block and the tool results exactly as before, so the English AppTests pass unchanged.
