- **Why:** the turn's graph is not checkpointed, so a pause inside its ToolNode would run the whole turn again (and call the model again) on resume; the pause belongs to the conversation graph (T9.4's note), after the turn, where the resumed node runs alone. The turn keeps the passing text in its context and returns it, so the arguments of the model's call never reach a checkpoint. A turn that only proposes would otherwise end "not covered" (no basis, AC-2), so it ends with a fixed line; the model is asked once more first, so "keep answers short; and how much protein?" is still answered (owner's choice after code review round 1). The checks run before the card and again at the save, so a client added in between, or an edit, is caught. `<memories>` sits in the user message before the question, so the system prompt stays the owner's fixed text and the thread keeps the question alone.
