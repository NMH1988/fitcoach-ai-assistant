- **Decisions & gotchas:** owner's choices (2026-10-26): `ToolNode` with a `wrap_tool_call` that runs every call through `registry.run_tool_call()` (LangChain's own `tool.invoke()` skips the check for tools without fields and its errors repeat the model's input), plus `end_round` for calls that are not JSON, which `ToolNode` ignores; our own `after_agent()` edge instead of `tools_condition`, as such a reply is a round too; the `UsageRecorder` in the run's context, not in state, because a node that raises loses its update and an error result keeps the tokens spent before it (the criterion is reworded in the plan). Mine, stated in the plan: a `prepare` node keeps the old order (prompts, index, translation model, answer model), so the same error is reported first; the graph is compiled once and what cannot be state (index, clients, callbacks) is context, ready for T9.4's checkpointer; the tools stay bound to the session's profile through the context. Gotchas: LangGraph counts the input as a step, so `recursion_limit` is `MAX_STEPS + 1` (with `MAX_STEPS` alone the four-round test failed); `ToolNode` runs calls in a worker thread, so `max_concurrency` is 1 to keep them in order, while the nodes (and so Streamlit's callbacks) run on the caller's thread (tested); a call's place in its round is found by identity, which relies on `ToolNode` passing the reply's own call objects (tested, so an upgrade that changes it fails); an exception leaves the graph with a note naming the task (no user text), and `BaseException` passes through. `src/agent/graph.py` imports `src.chat`'s helpers, so `chat` imports the graph inside its two functions. The `guard_rejected` line's `logger` field is now `src.agent.graph` (was `src.chat`); the tools are built on the first model request instead of before `on_profile_sent()` (they only build closures); an error raised by the caller's `on_step` for the first step now reaches the turn's catch-all, as for every later step, instead of leaving `run_turn()`.
