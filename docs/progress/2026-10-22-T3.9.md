- **Why:** with 20 credits the expander made the narrow sidebar long and wrapped each source over three or four lines; the modal is wide, so a source takes one or two.
- **Decisions & gotchas:** no `session_state` flag, unlike the profile dialog: the content is static, so a press draws the dialog in that run and the X closes it without a rerun. The dialog is built in the run of the press (`st.dialog(_t(...))`), so its title follows the language. With the profile form open a press opens nothing (Streamlit allows one dialog per run; AppTest raised without the guard, the browser's modal normally keeps the button out of reach). The button is drawn in an `@st.fragment` (`_about_button()`), so a press reruns only the fragment: Streamlit does not let a fragment's widget stop a running script (`_fragment_run_should_not_preempt_script` in `streamlit/runtime/scriptrunner_utils/script_requests.py`), so a press while an answer streams waits until the turn ends and the dialog opens then. Without the fragment the press reran the script and stopped the answer, losing it and the calls already paid for (PR #89 review); the expander it replaces made no rerun. AppTest neither shows fragments nor interrupts a run, so a test reads the decorator from `app.py`; the streaming case itself was not run in a browser (it needs the key). A dialog cannot hold an expander. In AppTest the dialog is `at.get("dialog")`, and its width is `proto.dialog.width`. Checked in the browser: opens at the large width, no console or server errors.
