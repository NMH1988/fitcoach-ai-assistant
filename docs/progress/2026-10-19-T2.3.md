## 2026-10-19 · T2.3 Build and open the Chroma index · #31 (closes #6)
- **Brief:** core requirement 1 (embeddings, similarity search); AC-13 (missing index).
- **What:**
  - `src/rag/store.py` (new): `build_index(chunks, embeddings, ...)` embeds the chunks in batches of `EMBEDDING_BATCH_SIZE` into a staging collection (cosine distance, the embedding model in its metadata) and renames it to `nutrition-sources` only when every chunk is in; `check_index()` returns the chunk count or raises `IndexNotReadyError` (missing, unreadable, empty, or built with another embedding model) with a fixed message that says to run `python scripts/build_index.py`; `open_index()` checks first, then opens the collection with our embeddings client; `chunk_id()` gives `<source_id>-<chunk_index>`.

  - `src/config.py`: `CHROMA_DIR`, `CHROMA_COLLECTION`, `BUILD_INDEX_COMMAND`, `EMBEDDING_BATCH_SIZE` (64).
  - Tests: `tests/test_store.py` (build and open in a temp dir with a `DeterministicFakeEmbedding` spy, batches, IDs, list metadata from the ingest fixture, rebuild, failed rebuild and failed first build, bad input, filters by topic, year, tier and source, every not-ready case), `tests/test_build_index.py` (summary, ingest error, missing key, a 401 from a mock server that echoes the key, an unwritable index directory, an index dropped while it opens). 810 tests pass.

- **Why:** a failed or interrupted build (an API error at batch 20 of 29, Ctrl+C) must not leave a half index the app would search without noticing, so the old index stays until the new one is complete. Stable IDs make rebuilds and later dedup (T3.3's RRF) simple. The model check stops a silent mismatch between stored vectors and query vectors if `EMBEDDING_MODEL` changes. `check_index()` needs no key, so a missing index is reported before a missing key.
