- **Why:** the views reuse the tools' own code (`macro_targets()`, `run_food_lookup()`), so the sidebar, the tab and the chat always show the same numbers and the same checks, with no model call. One palette that reaches 3:1 on every background was the only way that holds through a theme switch: `st.context.theme` can be wrong right after a switch in Streamlit 1.66, and a chart cannot be redrawn on it.
- **Decisions & gotchas:**
  - Owner's choices (2026-10-20, approving the plan's six defaults): one palette for both modes; "not found" suggestions as a plain-text table, not `st.pills` (labels read Markdown); g/lb to 2 decimals; a `protein_lowered` flag on the macro result (the model sees it in the tool JSON; the prompt needs no change); the kcal delta grey with its sign; the Food lookup tab skips the input guard and the rate limit, as it makes no API call.
  - Streamlit's chart theme colours legends and axes but leaves Vega text marks black, so the donut's kcal was unreadable in dark mode; `"color": "currentColor"` makes the SVG text take the page's text colour, and it follows a theme switch without a rerun (checked in the browser).
