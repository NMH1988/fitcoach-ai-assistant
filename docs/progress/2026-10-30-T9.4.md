- **Why:** Sprint 3's Medium 2 with LangGraph's own pieces (a checkpointer, a `thread_id`, `trim_messages`, `RemoveMessage`), while keeping D12's rule that chats never reach disk and the T9.3 rule of no profile block and no tool result in the messages (a kept answer may still restate a value a tool gave; compliance review, finding 1). Checkpointing the turn's graph itself would have stored its tool results (the macro targets hold `weight_kg`), its `<sources>` and the raw text of a rejected message in every checkpoint, and carried its per-turn keys over (T9.2's note); a small graph around it that keeps only messages avoids all of that.
- **Decisions & gotchas:**
  - Owner's choices (2026-10-30, Question phase): (1) the thread keeps the question and the answer only (the other option kept the whole exchange with profile values replaced and labels numbered across the conversation); (2) each turn still needs its own basis (AC-2), so "say that more briefly" gets "not covered" unless the model searches or calls a tool again (the other option let a reply rest on earlier answers, which would let an off-topic question through after one answer); (3) the owner writes O8's T9.4 part from Claude's list of points; (4) stored answers drop their `[S#]` citations, as the next turn's labels start at S1 again.
  - Defaults stated in the Question phase and kept: only answered turns are kept (not rejected, redirected, "not covered" or failed ones); "New chat" keeps the rate limit; the evaluation run passes no conversation.
  - LangGraph 1.2.17: `durability="sync"` on the conversation graph is inherited by the turn's graph, which has no checkpointer and fails on it (`_put_checkpoint_fut`); the default durability is used, as the run waits for its background saves before `invoke()` returns (the follow-up tests check it).
  - The turn's result reaches `run_turn()` through the run's context (`ConversationContext.results`), not state, since its tool runs hold tool results.
  - Found by the AppTest: a button drawn before the turn stayed off after the first question until the next rerun, so "New chat" is drawn into a slot filled after the turn.
