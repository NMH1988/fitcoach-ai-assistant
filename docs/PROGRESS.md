# Progress log

What each PR did and why, newest first. This file is the index: one line per entry, in the order the entries were added; each entry is a file of its own in `docs/progress/` (split out of this file, word for word, by T1.15). **Read this before starting a ticket**: this index, together with the open PRs (`gh pr list --state open`), and the entries of the tickets the new one builds on, changes or names as a follow-up, so earlier decisions and loose ends are not lost.

**Adding an entry:** every PR (Dependabot exempt) adds, in the same PR, so the log reaches `main` together with the work:
1. a file `docs/progress/<YYYY-MM-DD>-<ticket ID>.md` (e.g. `2026-11-11-T1.15.md`; `-2` added for a second entry of the same ticket on the same day), whose first line is the link back to this index (`[Progress log](../PROGRESS.md)`), then an empty line, then the entry in the format below;
2. one line at the top of the list below: `- [<the entry's heading without "## ">](progress/<file name>)`.

Keep the entry short and record what the code does not say. `tests/test_docs_layout.py` checks that every entry file has its line here, with the same text as its heading, and every line its file. Parallel PRs all add a line at the top, so they conflict here: keep both lines. `.gitattributes` sets `merge=union` for this file, which handles local merges; GitHub's web conflict editor ignores it. The entries written before T1.15 with no ticket ID in their heading (plans and the setup of 2026-10-19) have files named `<date>-plan-...` and `<date>-setup-...`.

**Numbers with `#`:** `#<PR>` and `closes #<issue>` refer to the personal repository where the work started, https://github.com/NMH1988/nutrition-ai-assistant (PR `#76` is https://github.com/NMH1988/nutrition-ai-assistant/pull/76); since 2026-10-26 the work continues in https://github.com/NMH1988/fitcoach-ai-assistant, whose issues and PRs are mostly written with the repository name (`NMH1988/fitcoach-ai-assistant#<n>`); in an entry whose heading names that repository, a bare PR or issue number may be one of its numbers (e.g. "PR #37" in T1.10's entry); issue and PR numbers in the course repository, if it has any, are unrelated. A source number (e.g. "#18a") is a row in `docs/SOURCES.md`.

```
## YYYY-MM-DD · T<x.y> <title> · #<PR> (closes #<issue>)
- **Brief:** by number in each brief: Sprint 3 (`docs/BRIEF_SPRINT3.md`): <item> or none; Sprint 2 (`docs/BRIEF.md`): <item> or none; "beyond the brief (owner's request)" only when neither covers it.
- **What:** files/behaviour changed.
- **Why:** reason for the approach chosen.
- **Decisions & gotchas:** anything a future session must know.
- **Follow-ups:** what is left, with ticket numbers.
```
