### T9.6 The SQLite store and the authorisation layer (L) · status: done · issue NMH1988/fitcoach-ai-assistant#9 (the copy of #101)
**Serves:** Sprint 3 (`docs/BRIEF_SPRINT3.md`): Medium 4 (personalisation; T9.5 adds the authentication), Medium 2 in part (the store T9.7's long-term memory writes to), core 4 (real-world use), evaluation: appropriate security; Sprint 2 (`docs/BRIEF.md`): Medium 4 (personalisation), evaluation: technical (appropriate security); beyond the brief (owner's request): the coach-client sharing model.
**Depends on:** T9.1, T8.2 (the canary log tests)
**Acceptance criteria**
- [x] `src/store/` uses the standard library's `sqlite3` on a file in a gitignored directory set in config (D13); a versioned migration function creates the tables of `docs/ARCHITECTURE.md` section 16, with foreign keys on, non-negative quantities checked and UTC timestamps (D21) - unit tests on a temporary database. Done: `config.STORE_DIR` (`data/store/`, gitignored) and `config.STORE_PATH`; `db.connect()` turns foreign keys and `secure_delete` on, keeps temporary data in memory (`temp_store`) and, on POSIX, makes the app's folder and the file owner-only and runs `db.migrate()`, which applies `schema.MIGRATIONS` by `user_version` in one transaction and refuses a newer file; 15 STRICT tables (section 16, with the changes recorded there: `audit_log.subject_id`, `meal_items.consumed_on` and `food_name`, `ai_reviews.period_start`); CHECKs on every quantity, role, scope and status, and on every timestamp (UTC, `+00:00`) and day (ISO). `tests/test_store_db.py`; `tests/conftest.py` points every test at a temporary file.
- [x] Every query is parameterised - a scan test fails on SQL built with f-strings, `%`, `.format()` or `+` in `src/store/`. Done: `tests/test_store_sql_scan.py` refuses any string built at run time in `src/store/` (f-strings, `%`, `+`, `+=`, `.format()`, `.join()` of SQL) and any `execute*` whose query is not a literal or a module constant (migrations from `schema.MIGRATIONS` allowed and checked), with cases it must catch and cases it must pass.
- [x] Every read of another user's data takes the acting user and checks the role, an active relationship and the scope; a missing, foreign, ended or unshared resource gives the same `NotFound` (D16) - cross-client tests for every read function (AC-21, AC-22). Done: `access.authorised_read()`; scopes as the owner chose (2026-10-27): body = weights and profile entries, nutrition = meals, targets and the coach's own reviews, training = workouts, preferences never shared; a coach's own list and export of their reviews keep only clients who still share nutrition (one audit row per client read), and a gymer never gets the model's draft (owner's choices after the code review). `tests/test_store_access.py` also fails on any public store function that is not classified as a tested read, own-only, a write or an internal. `tests/test_store_access.py`: every `list_*` function (a test fails if one is added without being listed) against ten refused cases, a scope off while the others are on, revoking and ending (AC-22); the same `NotFound` and no audit row each time.
- [x] Nutrient snapshots and profile entries are never changed in place, and a new target is a new row - unit tests. Done: a trigger refuses any UPDATE on the record tables and the audit log, and on a decided review; the modules have no update function. Beyond the criterion (from the reviews): the store also keeps the profile form's ranges (adults only), the calorie floor on every target and records for gymers only. `tests/test_store_records.py` (snapshots, profile entries, targets) and `tests/test_store_db.py` (every record table).
- [x] A coach's read of client data and every review decision write an audit row with no values - unit tests. Done: `access.audit()` writes IDs, the action, the kind of data and the time only; a coach's read writes it in the read's transaction (the coach's own review list and export write one per client read), `reviews.decide_review()` in the decision's. `tests/test_store_access.py`, `tests/test_store_reviews.py`. A refused read is not audited (owner's choice, 2026-10-27).
- [x] `export_user_data()` returns all of a user's rows as JSON; `delete_user_data()` removes them, the user's relationships, the reviews about the user and those the user wrote as a coach, and the audit rows by or about the user (the app is local and keeps no audit duty; the owner may change this) - unit tests with foreign keys on (AC-34); T9.16 adds the review threads. Done: `src/store/my_data.py`; a gymer's export holds the approved reviews about them without the model's draft, a coach's the reviews they wrote about clients who still share nutrition (what each reads); the owner accepts a gymer's export without pending or rejected reviews as meeting AC-34 (2026-10-27). `tests/test_store_my_data.py`: no column names the user after the delete, `foreign_key_check` is clean, other users' rows stay, and a table the delete forgets makes it fail with nothing changed.
- [x] No stored value appears in a log record - T8.2's canary tests extended to the store (AC-33). Done: `tests/test_observability.py::test_no_record_or_error_holds_a_stored_value` runs every store function with canary values at DEBUG and checks every log line and every error's text; the store writes no log line.
- [x] `.claude/rules/security-privacy.md`, `docs/PRD.md` (feature 4 and the privacy note) and `docs/SECURITY.md` (what is stored, where, for whom and how it is deleted; a shared machine, a copied file; the file is not encrypted; local only) are updated - owner review. Approved by the owner on 2026-10-28 (after the compliance review and its fixes), then corrected after the final compliance and security runs on 608bb83 and code-review rounds 7-11 (who sees the relationship, its audit rows now named as the coach's reads and review decisions; who sees which display name, and the T9.12 exception for it; what a gymer reads of a review; the rollback journal; `temp_store`; what the sharing pattern check covers; the SQL scan's coverage, the refusal of text that cannot be stored and no error kept as context; the PRD's "shares a gymer's records and reviews"); and the owner confirmed the corrected sentences on 2026-10-28: the rule's "Personal data" section, PRD feature 4 and "The privacy change", and in `docs/SECURITY.md` an asset, three threat rows (reads by someone not shared with, SQL injection, data on disk) and the known limits (the store trusts the acting user it is given; permissions, the rollback journal, re-sharing a scope).
