### T7.1 Language switch: English and German UI (M) · status: done · issue #33
**Serves:** Hard 4 (multi-language support), as an extra after the core; AC-16. Changes the PRD's English-only decision: beyond the PRD (owner's request, 2026-10-20).
**Depends on:** T4.4, T4.7, T5.3 (so most UI text and the guardrails exist before they are translated), T1.3, T7.4 (the German guard and guardrails, split from this ticket on 2026-10-21)
**Acceptance criteria**
- [x] `src/i18n.py` holds every user-facing UI string in English and German behind one lookup function; a test fails if a key exists in one language but not the other - unit test (`tests/test_i18n.py`: `test_every_key_exists_in_both_languages`, `test_each_text_is_filled_and_has_the_same_placeholders_in_both_languages` for each of the keys; the English entries that the model, the guard or the PDF also use are checked against their modules).
- [x] The header has a language control (a `:material/translate:` icon next to an EN | DE segmented control labelled "Language", label collapsed, `required=True` so it can never be deselected to `None`); switching it changes all UI text (sidebar, tabs, buttons, errors, guard and guardrail messages, disclaimer) - AppTest in both languages (`tests/test_app_language.py`: the control's label, collapsed label, options and `required`; the German header, disclaimer, tabs, sidebar and PDF button; the profile form and its errors; the targets with German numbers; a guard rejection, a guardrail redirect, the "not covered" message and a past message switched back; the Details tab, its usage table and the tool results after an answer, with a check that no English UI text is left on the page; the Food lookup tab's four German messages; every turn's message key checked to exist in both languages (`turn_codes_are_keys` in `tests/conftest.py`); the existing English AppTests pass (one source scan now looks for `_t("theme.hint")`); accessible name checked in the browser, `docs/TESTING.md`).
- [x] The default language follows the browser locale (`st.context.locale`: German for `de*`, English otherwise, including `None`; changed by T9.5 at the owner's choice of 2026-11-02: English for every session) and the user's choice is kept for the session - unit test on the locale mapping and AppTest (`test_a_german_browser_locale_gives_german`, `test_any_other_locale_or_none_gives_english`; `test_a_german_browser_starts_in_german`, `test_the_choice_is_kept_for_the_session`, `test_the_browser_locale_is_read_only_at_the_start`; the locale is set on a session's first run, checked in the browser).
- [x] Source titles, licence names and USDA food names stay in English; the Food lookup tab tells German users to enter English food names - AppTest (`test_an_answer_keeps_its_text_and_its_sources_stay_english`, `test_the_food_lookup_tells_german_users_to_use_english_names`).
- [x] The German texts, the medical disclaimer in particular, are reviewed by the owner or a German speaker before merge - manual check recorded in `docs/PROGRESS.md` (the owner reviewed all 259 texts on 2026-10-21, the four Food lookup tab texts after the others, no change asked).
The German guard and guardrail criteria moved to T7.4 (owner's decision, 2026-10-21).
**Notes:**
- The German safety checks are in T7.4 (split from this ticket), not T7.2, because a German UI invites German input even if T7.2 is cut; T7.4 merges first.
- Owner's choices at the start (2026-10-21): the summary PDF stays English here and becomes German in T7.2 (its criterion); tool-produced text (the targets' message and notes, the TDEE method, food and meal plan messages) stays English in the chat's tool results and the My targets tab, while the Food lookup tab, which calls no model, shows its own messages in German (changed in the review of PR #74); the owner reviews the German texts. Past turns' fixed messages (guard, errors, "not covered") follow the language chosen now; the model's answers stay in the language they were written in (default stated in the Q phase).
- Many messages come from `src/` (guard rejections and rate limit in `src/guard.py`, LLM errors in `src/llm.py`, `IndexNotReadyError` in `src/rag/store.py`, profile validation in `src/profile.py`). `src/` returns message keys or codes and the UI translates them. Tool notes stay English, so the tool result the UI shows matches what the model received. The size was rechecked at the start (closer to L), hence the T7.4 split. `chat.format_profile()` reads the profile labels for the model's `<profile>` block, so translated labels must stay out of it.
- The German UI texts are our own writing. Every UI string added after T7.1 needs both languages.
