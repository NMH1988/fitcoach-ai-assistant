**Acceptance criteria** (proposed by Claude and approved by the owner on 2026-11-19; criteria 4, 5 and 7 tightened after code review round 1 of NMH1988/fitcoach-ai-assistant#154, approved by the owner the same day)
- [ ] **`chat` by concern.** `src/chat/` holds modules by concern (proposed: `results` for the turn's types and errors, `prompts` for the answer prompt and its version, `retrieval` for `find_chunks()` and its filters, `citations` for the sources block, the citation labels, the source cards, the manifest and the knowledge base summary, `markdown` for escaping, image removal and the paced writer, `messages` for the model messages, the history's trimming and the fixed texts, `answer` for `stream_reply()` and `answer_with_tools()`, `turn` for `TurnDeps`, `TurnCallbacks`, `run_turn()` and its log line; the exact split set in the Structure phase), and `src/chat/__init__.py` re-exports every public name, so `chat.X` and `from src.chat import X` keep working in every caller unchanged - a test that the package's public names equal the old module's (listed in the test), each defined in one module, and the existing tests.
- [ ] **No module over a size limit.** No module of `src/chat/` is over 600 lines - T10.8's size test (`tests/test_config_package.py`) covers `src/chat/` too.
- [ ] **No behaviour change.** No test is deleted, skipped or loosened (only patch targets and paths change); the number of tests and the coverage of `src/chat/` and `src/agent/` are not lower - the before and after counts in the PR description.
- [ ] **Patches still land where they did.** The tests that patch a name a submodule uses from inside (today `embed_queries`, `load_manifest` and `_NUTRITION_ONLY`, in `tests/test_app_chat.py`, `tests/test_app_usage.py`, `tests/test_chat.py` and `tests/test_retrieval_regression.py`) patch the submodule that uses it, so the patches still take effect; the names tests patch on the package itself (today `run_turn`, `manifest_by_id`, `load_system_prompt`) are still read by their callers through `chat.X` - the existing tests with their assertions unchanged, and a scan test like T10.8's that finds by AST the names a module of `src/chat/` reads by bare name (its own, another module's of the package, or an imported one) and refuses a test that patches one of them on the package alone.
- [ ] **Imports still resolve.** The package imports cleanly in a fresh interpreter whichever module is imported first: `src.chat`, or any module that imports it at the top (today `src.agent.graph`, `src.agent.memory`, `src.agent.review`, `src.agent.search`, `src.export_pdf`, `src.weekly_review`); whether the lazy imports of `src.agent.graph` and `src.agent.search` stay is set in the Structure phase - a test, one fresh interpreter per module.
- [ ] **The scans still see everything.** `tests/test_client_rules.py` (which names `src/chat.py`) and any other test that reads `src/chat.py` by path cover the package's modules - the existing tests, pointed at the new paths with the same assertions.
- [ ] **Docs and rules match the code.** `CLAUDE.md`, `.claude/rules/`, `.claude/agents/`, `docs/ARCHITECTURE.md` (the module tree), `docs/DIAGRAMS.md`, `docs/SECURITY.md`, `docs/TESTING.md`, and the docstrings and comments in `src/`, `views/`, `scripts/` and `tests/` that name the file (e.g. `src/prompt_data.py`) - a search for `src/chat.py` finds none outside the records (`docs/progress/`, old tickets, the plan's status line in `docs/IMPLEMENTATION_PLAN.md`, `docs/BRIEF_SPRINT3.md`, which records the reviewer's point) and test data that only uses the path as a sample (the fake `git diff` in `tests/test_eval_results.py`).
- [ ] **Reviews.** `code-reviewer`; `/security-review`, as the escaping of the question and the chunks (`user_message()`, `format_sources()`), the image removal and the turn's log line move (unchanged); each report posted on the PR. No `compliance-reviewer` run: nothing its rule covers changes (the log line and the model messages move word for word); the PR description says so.
