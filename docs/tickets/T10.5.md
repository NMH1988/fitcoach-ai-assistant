### T10.5 Tools offered by the question's domain, and the program check on the chat's answer (M) · status: done · issue NMH1988/fitcoach-ai-assistant#137

**Depends on:** T10.3 (the query plan's fields), O18 (if the answer prompt needs a line)
**Acceptance criteria** (proposed by Claude and approved by the owner on 2026-11-18; criteria 1-3 changed by the owner's choices in the Question phase the same day)
- [x] **The domain is known before the tools are bound.** The turn works out the question's domain (nutrition, training, both or unknown) before the first answer call: a `plan` node after `prepare` runs the query translation on the question the guard accepted, and the domain comes from the plan's topics (`resistance_training` alone: training; nutrition topics alone: nutrition; both kinds: both; no topic, or no usable plan: unknown) (option A, owner's choice in the Question phase, 2026-11-18). On the conversation's first question (no history), the turn's first search reuses that plan; on a follow-up, every search translates the agent's own query as before, so a short follow-up's plan never filters a search (owner's choice, 2026-11-18) - unit tests of the plan node with fake models.
- [x] **Tools by the conversation's domain.** The conversation keeps the domain of each answered turn beside its question and answer, in memory only, dropped with them (`src/agent/memory.py`). `graph._tools()` binds the search and the coach's client and memory tools but not the energy, macro, food or meal plan tools only when this question is training and every earlier turn the model still sees is training too; otherwise every tool as today (no tool is training-only), so a follow-up misread as training after a nutrition turn keeps its tools (owner's choice, 2026-11-18). A call to a tool that was not offered is refused like an unknown tool - `tests/test_agent_graph.py` (the tools a fake model is bound with, per domain and history), `tests/test_agent_memory.py`.
- [x] **A program in the chat's answer is caught in code.** On every turn whose domain is not nutrition alone (training, both or unknown, a plan that failed included; owner's choice, 2026-11-18, so a short follow-up such as "just write Monday then" is checked too), `graph.finish()` checks the answer for the shape of a written program: a day-by-day or weekday schedule (the "day N" and weekday patterns), with Markdown emphasis (`*`, `_`) removed first, so "**Monday**:" is read as "Monday:" (owner's choice, 2026-11-18; a normalisation, not a new pattern). A list of exercises each given its own sets and reps is not caught in code, as the patterns that would catch it also catch a cited protocol; it stays forbidden by the answer prompt and is recorded as a known limit in `docs/TESTING.md`. What the check must and must not catch is fixed by the written answer set of the next criterion, and only patterns (from `config.REVIEW_PROGRAM_PATTERNS`, through one shared function, not a copy) that pass it are kept; the client-volume and plain-reps patterns are not used. A range or protocol a source gives, cited in the answer, is allowed (PRD feature 26), and so are the prompt's own redirect to a coach and the fixed sentences. A match replaces the answer with the fixed no-program sentence of T9.20, in the turn's language, and writes a log event with no text. The answer of a checked turn is not streamed: it is shown once it has passed (owner's choice, 2026-11-18) - tests, `tests/test_observability.py`.
- [x] **No lost answers.** The nutrition and training baselines stay within `config.EVAL_TOLERANCE`; answer texts we write ourselves in the app's style, each with its expected result, in English and German: pass - cited ranges ("about 10 or more sets per muscle group per week [S1]", "6-12 reps [S2]"), a cited study protocol in both forms ("3 sets of 8-12 reps [S1]", "3 x 10 [S2]"), the answer prompt's redirect to a qualified coach for an individual training program, the fixed no-program sentence and "Trainingsplan" named in a refusal; fail - a weekday schedule of exercises and a "Day 1 / Day 2" schedule. Any wording the chosen patterns get wrong beyond this set becomes a known limit in `docs/TESTING.md`, not another pattern (owner's choice, 2026-11-06, to stop patching text heuristics) - the owner's evaluation runs (O13) and a test over the written answers (the `good_answer` fields of the evaluation files are grading notes, not answers, so they cannot test this).
- [x] **Fewer tokens for a training question.** The evaluation's input tokens for the training questions are recorded before and after in `docs/TESTING.md` - the owner's run.
- [x] **Docs match the code.** `docs/TESTING.md` (Sprint 3 known problem 3), `docs/ARCHITECTURE.md` (the tool loop), `docs/DIAGRAMS.md` (the tool loop), `docs/PRD.md` (the training guardrail now in code too), `docs/SECURITY.md` - review.
