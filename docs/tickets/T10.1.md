### T10.1 Answers checked for injected instructions before the chat's memory keeps them, and a measured miss rate (M) · status: todo · issue NMH1988/fitcoach-ai-assistant#133
**Serves:** Sprint 3 (`docs/BRIEF_SPRINT3.md`): Sprint 3 review point 1; Medium 8 (a security guard against misuse); evaluation: appropriate security, error scenarios and edge cases; Sprint 2 (`docs/BRIEF.md`): Medium 3 (prompt injection protection); core 3 (security measures relevant to the domain).
**Depends on:** -
**Acceptance criteria** (proposed by Claude on 2026-11-18; awaiting the owner's approval)
- [ ] **The answer is checked before the thread keeps it.** In `src/agent/memory.py`'s `turn()`, an answered turn's text goes through `guard.looks_like_injection()` before `chat.exchange_messages()` is returned to the thread; a flagged answer is not kept, so the thread stays as it was (as for a rejected or "not covered" turn), and the next turn's messages hold neither its question nor its answer - `tests/test_agent_memory.py` (a canary instruction in a fake model's answer is absent from the next turn's messages; a clean answer is kept as today).
- [ ] **What the user sees** follows the owner's choice in the Question phase (see Notes): by default the answer already shown stays on screen, with a one-line note in English and German that it will not be remembered in this chat - AppTest (`tests/test_app_memory.py`).
- [ ] **A log line with no text.** A dropped answer writes one new event (`memory_answer_dropped`, added to `observability.EVENTS`) with the `turn_id` and no question, answer or matched pattern - `tests/test_observability.py` (canary values).
- [ ] **No false alarm on the app's own answers.** The check flags none of a set of answer texts we write ourselves in the app's style (cited answers, refusals, "not covered" replies, the coach's client answers; English and German; the `good_answer` fields of the evaluation files are grading notes, not answers) - a test; and the number of answers it flags in the owner's evaluation run is recorded in `docs/TESTING.md` (O13).
- [ ] **An offline red-team fixture with a recorded miss rate.** `tests/fixtures/red_team_injections.json`: at least 40 attacks written for this repo (no text from any outside source), in English and German, grouped by kind (role change, rule override, prompt leak, output-format hijack, link or image exfiltration, an instruction phrased as a source's text), each a paraphrase of a pattern the guard already knows or a new wording; plus at least 20 harmless gym questions that use the same words ("ignore the soreness", "act fast after training"). A test computes the guard's miss rate on the attacks and its false-alarm rate on the harmless set and fails if either is worse than the numbers recorded in the fixture (a ratchet, so a later change can only lower them) - the test; both rates written in `docs/TESTING.md`.
- [ ] **The classifier option is weighed, not built.** `docs/SECURITY.md` records the option of a small structured-output classifier (`{"is_instruction": bool}`) on retrieved or remembered text: its cost per turn (calls and tokens, at OpenRouter's prices on the day), its latency, and that the classifier reads attacker text itself and so can be injected; the owner's decision on it is recorded - review.
- [ ] **Docs match the code.** `docs/TESTING.md` (Sprint 3 known problem 5), `docs/SECURITY.md` (the chat's memory), `docs/ARCHITECTURE.md` (the conversation graph) - review.
- [ ] **Reviews.** `code-reviewer`, `/security-review` (the guard), `compliance-reviewer` (a test fixture that holds text), each report posted on the PR.
**Notes:** files: `src/agent/memory.py`, `src/guard.py` (read only, unless the owner wants patterns added), `src/observability.py`, `views/chat.py`, `src/i18n.py`, `tests/fixtures/`. **For the owner (Question phase):** (1) what a flagged answer does on screen: stays shown and is not remembered (Claude's suggestion: it was already streamed, and hiding it after the stream is confusing), or is replaced by a fixed message; (2) whether this ticket also adds patterns for the misses the fixture finds, or only measures (Claude's suggestion: only measure; patterns tuned on the fixture would lower its miss rate without showing that new paraphrases are caught, and the owner chose on 2026-11-06 to stop patching text heuristics in loops). The guard's patterns were written for user input; an answer that quotes the user's own attack is flagged too, which is the wanted result. Retrieved chunks are not checked by the patterns in this ticket: they are CC BY articles already delimited and escaped (T3.4), and a pattern hit on a research text would most likely be a false alarm.
