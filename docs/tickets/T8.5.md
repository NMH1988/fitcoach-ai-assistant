Sprint 2 (`docs/BRIEF.md`): Hard 7 (RAG evaluation), which it runs on every PR, and Hard 1 (hybrid search), which it guards.
**Depends on:** T8.4
**Acceptance criteria**
- [x] A fixture index is built in a temporary directory from short texts we wrote ourselves (no article text: copyright policy rule 8; owner's choice, 2026-10-25), with a deterministic fake embedder, through the same ingest metadata and `store` code as the real index - fixture in `tests/fixtures/`. Done: `tests/fixtures/retrieval/sources.json` (twelve made-up sources, read by `load_manifest()`, the loader of `data/sources.json`) and `suite.json` (their 30 short sections, one chunk each, all written for the tests); `ingest.chunk_article()` and `store.build_index()` build the index in pytest's temporary folder, with `ConceptEmbeddings` (each of 14 concept word groups is a dimension, plus a small constant; `DeterministicFakeEmbedding`'s random vectors are about 1.0 apart, so no question would pass the gate); `test_the_fixture_index_is_built_by_the_ingest_and_store_code`, `test_the_concept_embeddings_put_shared_concepts_close_and_off_topic_text_far`.
- [x] A suite of fixture questions with expected chunk IDs runs the real pipeline (filters, the gate, BM25, RRF, the per-source cap) and fails if the hit rate at `RETRIEVAL_TOP_K` drops below the rate recorded in the fixture - `tests/test_retrieval_regression.py`, run by the ordinary CI test job with no key. Done: nine questions through `chat.find_chunks()` (the search the agent's tool runs, the filter retry included) with the fixture's plan in place of query translation and the config's own `RETRIEVAL_TOP_K`, gate, `RRF_K` and cap. Owner's choices (2026-11-09): the hit rate counts expected chunks, not questions (recorded 0.8888, 8 of 9); off-topic questions have their own no-sources rate (recorded 1.0, 2 of 2); one known miss stands for q10's #8 (T8.3). The training retry is checked to return training chunks only (`only_topic`, code review round 1). `test_the_rates_do_not_drop_below_the_recorded_ones`, `test_only_the_known_misses_are_missed`, `test_the_fixture_questions_and_recorded_rates_are_well_formed`.
- [x] A deliberate break (for example the cap set to 1, or BM25 removed) makes the suite fail - shown once in the PR description. Done: `MAX_CHUNKS_PER_SOURCE = 1` in `src/config.py`, run once and reverted (the rate test and the known-misses test fail, `cap_second_chunk` losing `2-1`), in the PR description; and, by the owner's choice (2026-11-09), six permanent tests (`test_a_deliberate_break_drops_a_rate_below_the_recorded_one`: a cap of one, no cap, no BM25, the plan's filters ignored, no gate; and `test_a_retry_that_searches_everything_lets_a_nutrition_chunk_into_the_training_answer`), so the fixture stays sensitive to each step.
**Notes:** this catches pipeline bugs, not embedding quality; T8.6 covers the real model. The fake vectors are meaningful only within the fixture: a legitimate change to `RETRIEVAL_TOP_K`, the gate or the cap can move a recorded rate, and lowering one is a decision recorded in `docs/TESTING.md`. Not covered: query translation (each question's plan is fixed in the fixture), the chunk splitting of long sections (each section is one chunk), and the nutrition-only retry (`tests/test_chat.py` covers it).
